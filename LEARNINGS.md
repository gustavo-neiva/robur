# Learnings

> Append-only guardrails the agent discovers while working on this repo.
> Read this before each turn; add new gotchas you hit (one bullet per line).
> A planner turn prunes stale entries periodically. The loop never depends on
> this file — it is advisory memory, not state.

- _(example)_ `npm test` must run from the repo root; a nested cwd makes it red.
- `File.expand_path("../lib", file_path)` keeps the filename — always expand against `File.dirname` (cost a turn in T1.1).
- `parse_repo_conf` truncates `.ratchet.conf` values at the first `#`: a `VERIFY_CMD` containing Ruby interpolation like `#{...}` is silently cut in half and RED-locks the loop. That is why the gate uses `File.expand_path(f)` instead of interpolation. Never put a `#` in any `.ratchet.conf` value.
- `exe/robur` resolves `lib/` relative to its own path: a copy of the script outside the repo dies with `LoadError` before printing anything. Differential-harness mutants need a shadow tree with `lib/` beside the mutated script.
- Differential parity needs per-side path normalization, not just tmp-root: each side's RATCHET_HOME basename ("home-base"/"home-cand") and the repo path (now `<home>/repo`, shared basename) leak into stdout and `last-log`; the slug's 6-digit cksum of the abs path also differs per side and is normalized to `<slug>`.
- Baseline help prints a blank line between the usage body and the `Config:` line, and baseline log files can carry invalid UTF-8 — the harness scrubs before gsub or it raises ArgumentError.
- `exe/robur` resolves `lib/` beside itself, so a differential mutant must copy BOTH `exe/robur` and `lib/` into the shadow tree; mutating a lib copy while pointing candidate_cmd at the real exe silently tests the unmutated code.
- M1 self-QA (T1.7): both gates green — unit gate 4 runs / 9 assertions, 0 failures; diff gate `0 diffs across 3 scenarios` (help, unknown-flag, doctor). Harness invocation lives in AGENTS.md under Gates.
- `exe/robur` must require every lib file a command touches — `robur/config.rb` was missing, so doctor crashed with NameError only once a `.ratchet.conf` existed (M1's no-conf path never loaded it). New commands: add the require, or the differential suite is the only thing that catches it.
- Doctor conf-error parity has three separate surfaces: the leading blank indented line (bash errors string starts with `\n`), the `main()` stderr WARNING emitted with the RAW dir arg (`REPO_DIR` is not resolved until after the warning), and the VERIFY_CMD first-token executable check. Robur's `warn` maps to stderr; keep timestamps on the warning line only.
- Baseline allows `COOLDOWN_<PROVIDER>` but NOT `MODEL` — the allowlist key is `MODELS`. A suite scenario with an unallowlisted key silently turns "valid conf" into "unknown key".
- bash `emit` tees every line to `$LOOP_LOG` once main() wires the logs up (common.sh:108), so `once` must append its preflight lines to loop.log or the file-surface diff flags an empty-vs-written log.
- Differential snapshot keys can COLLIDE after normalization: both sides' `home/logs/<slug>/loop.log` normalize to the same surface name, and a naive union-key loop pairs each side against nil. Group snapshot keys by normalized name before building surfaces.
- Doctor tracker parity is three-way: `tracker_has_open` is a plain grep (`^[[:space:]]*-?[[:space:]]*\[ \]`, no heading skip), done-count is lowercase `[x]` only, and there is a "task id unresolved on first open task" FAIL when the first open task has no id — robur's old `/^- \[ \]/` anchor missed indented checkboxes.
- `Turn.run`'s watchdog loop checked the deadline BEFORE `Process.waitpid2`, so a process that finished within the same poll tick the cap was reached got misclassified as a `deadline-Ns` kill (exitcode 128, `took` bumped by the 2s TERM grace period) instead of its real exit status. Bash's `while kill -0 $pid` checks liveness first; check `waitpid2` first in the Ruby loop too, every tick.
- `run_once_loop`'s last statement was `metrics_append`, whose body ends in `File.write` — that return value (byte count, e.g. 76) silently became the process exit code via `exit(Robur::CLI.run(ARGV) || 0)`. Any command function that reaches `exit()` needs an explicit final value; don't let a helper's return type leak into the exit status.
- `emit`/`term_only` never read `QUIET` — bash's `emit` is log-only once `QUIET=1` and `LOOP_LOG` is wired, and `term_only`/`flow`(-equivalent excerpt printing) must gate the same way. `@quiet` has to be set from conf BEFORE the first `emit` call (the preflight line), matching bash's config-before-dispatch order in `main()`.
- Redirecting `HOME` for the differential harness breaks EVERY asdf shim on the PATH, not just ruby: bash ratchet's `_turn_usage` shells out to `python3`, and under a redirected `HOME` (no `.tool-versions`) the asdf python shim fails and its bash fallback (`|| printf '0\t0\t0\n'`) silently swaps `%.6f`-formatted costs for a bare `0`. Pin `ASDF_PYTHON_VERSION` (and apply `asdf_env` to the baseline side too, not just candidate) alongside `ASDF_RUBY_VERSION`.
- Full turn-level differential scenarios can't demand parity on surfaces a later milestone owns: `commit_turn` is a deliberate M5 stub (T5.2), so git log / loop.pid / loop.log commit lines will never match baseline until then. `Scenario#only` (harness.rb) scopes a scenario's `differences` to a named/patterned surface allowlist instead of comparing everything the harness happens to snapshot.
- Wall-clock `took` fields are inherently racy even on a matching code path: metrics.tsv's `turn` row can tick across a 1s boundary differently per side under load. Blank the `took` column when splitting metrics.tsv into per-event surfaces (`split_metrics_rows`) rather than adding a blind digit normalizer that could hide real timing regressions elsewhere.
- `Turn.run` never passed `chdir:` to the spawned agent, so a multi-turn loop test (cwd = the runner's dir, not the repo) ticked the WRONG PLAN.md forever — bash's `main()` `cd`s into `$REPO_DIR` before every turn (`ratchet/bin/ratchet:422`); the loop and the classifier-stub CLI path both need `Turn.run(..., chdir: dir)`.
- `Plan#all_lines` memoized (`@all_lines ||=`) — one `Plan` held across the run loop's turns kept reading turn-1's PLAN.md forever even though the agent rewrote the file every turn. Never memoize a file read a long-lived object re-reads across external mutation; bash re-`cat`s the tracker on every `tracker_*` call.
- `test/fixtures/fake-agent`'s python heredoc dropped the closing `]` when marking a task `[IN PROGRESS` (missing bracket) — invisible to bash suite 8 because it only ever runs one `once` turn, but a multi-turn `run` loop test exposed it: task 2 was never matched as in-progress or open again. Fixed in robur's copy only (one byte); the differential harness uses robur's own `test/fixtures/fake-agent` for BOTH sides, so this doesn't diverge from `../ratchet`'s parity contract.
- `MAX_DONE_GATE_FAILS` only accumulates when the tracker has ZERO tasks (not zero open with some done): the all-done fast path requires `count(:done) > 0`, and the ALL_DONE-with-open-tasks downgrade only fires when `open?  || in_progress?` is true. An empty tracker satisfies neither, so a `done`-classified turn reaches the `case :done` gate-fail branch every time — this is the only state that reproduces the `MAX_DONE_GATE_FAILS` stop.
- M5 differential scenarios can't put `.ratchet.conf` under git: it carries `VERIFY_CMD`/`AGENT_CMD` absolute paths that differ per side, so it's untracked in every scenario and excluded before the staged-diff check (harness normalizer). The conf-tamper scenario proves the gate excludes the conf BEFORE secret-scanning by planting an AWS-shaped value in an allowlisted, behaviour-inert key (`FANOUT`) — if the exclude were missing, the scan would block the turn's real commit and git log would diverge.
- Moving `doctor_report` out of `CLI` into `Commands.doctor_report` left `cmd_once`'s preflight call pointing at the now-deleted local method — it silently raised `NameError` inside `run_once_loop`'s caller, printing only the "preflight (doctor) ..." line before dying, and the M5 differential suite (real turn commits) caught it while the smaller `doctor`-only M1/M2 suites did not exercise that code path. Grep every caller of a method before moving it, not just its own tests.
- `Commands.doctor_report`'s tier-routing block was hardcoded static text (`PLAN : → MODELS (flat) (thinking=)` etc.) regardless of conf — it never reflected `PLAN_MODELS`/`LIGHT_MODELS`/etc. or emitted the `AUTOPLAN_MODELS unset` / `LIGHT_MODELS without THINKING_LIGHT=off` WARN lines bash prints. Wired it through `Tier.chain_for`/`Tier.thinking_for` on the repo-only `conf_values` (not full `Config.load`, matching how `AGENT_CMD`/`VERIFY_CMD` already read doctor's conf) to get dynamic parity.
- `robur/templates/` is a byte-identical COPY of `ratchet/templates/` (ratchet.conf.example, AGENTS.human.md, LEARNINGS.md, PLAN.seed.md) — `init`/`new` must not read `../ratchet/templates` at runtime, since robur is meant to survive a rollback where the bash ratchet repo is gone.
- `CLI.posix_cksum`'s length-append loop was `8.times { upd.call(len & 0xFF); len >>= 8 }` — always 4 extra zero-length bytes past what POSIX `cksum` feeds in (it appends only the nonzero length bytes, LSB first, stopping once the remaining length is 0). Every `project_slug` disagreed with bash's, so `robur status` and `ratchet status` read DIFFERENT `RATCHET_HOME/logs/<slug>/` directories and always showed "no loop.log found". Fixed to `while len.positive?`; verified against real `cksum` on `""`, `"a"`, `"ab"`, `"123456789"`.
